Kubernetes · Deployments

Production Kubernetes & release validation

Every release and every incident ends with the whole application flow verified.

Problem

After a build, a server change or an outage, "pods are running" did not always mean the application actually worked end to end.

What I do

Deploy with ArgoCD and Helm, then validate the full flow: pods and probes, services, ingress and the real request path. Troubleshoot networking (Calico), storage and resource limits, and document fixes as reusable runbooks.

Result

Releases and recoveries are confirmed working for users, not just started, and repeat issues are fixed once for the whole team.

R&D · OpenObserve

Unified observability platform

Built from zero: one screen to go from an alert to its root cause.

Problem

Logs, metrics and traces lived in different tools, so finding the cause of an issue meant jumping between them.

What I built

OpenObserve on Kubernetes with OpenTelemetry agent and gateway collectors; trace_id in every log line across Java services, WSO2 ESB/APIM, NiFi and data-lake engines; trace dashboards; 45 alert pipelines and 83 real-time alerts.

Result

All 50 of 50 end-to-end trace checks passed, and one place to investigate any production issue.

Grafana · Data Lake House

DLH service overview dashboards

The health of a 13-service data platform, with live alerts, on a single screen.

Problem

Airflow, Trino, Spark, Kafka, Druid, MinIO and the rest had no shared health view, and some dashboards had no data at all.

What I built

The OSS Engine Overview plus 13 per-service dashboards showing UP / DOWN / UNREACHABLE, latency, JVM and pod health, a service-health table and a live alerts panel filtered by severity; added the missing scrape jobs and fixed broken exporters (Kafka, Solr).

Result

Every service's state is visible at a glance, from ingestion through storage and processing to query.

Distributed tracing · Vendor API

I999 emergency call, end to end

Followed one emergency call across six systems in a single trace.

Problem

An incident call from the I999 vendor passed through the API gateway, ESB, Vault, IoT services and the command centre, and delays between them were invisible.

What I built

One trace covering every hop, including the background fire-station recommendation, plus a step-by-step guide so the team can read any call in OpenObserve.

Result

Per-hop timings showed where time went, and confirmed the impact of replying to the caller earlier.
